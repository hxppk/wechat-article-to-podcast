# 技术设计：播放详情页与分享入口

## Context
当前播放器提供基础播放与列表能力，但缺少详情页、分享入口与原文跳转，无法满足内容确认与传播需求。本改动以前端扩展为主，复用已有播客元数据与接口。

## Goals / Non-Goals

### Goals
- 底部抽屉式播放详情页，展示标题/公众号/简介/时长
- 详情页分享按钮生成可访问链接并复制
- 详情页提供原文跳转入口
- 增加快退 15s / 快进 30s 控制
- 分享链接进入后自动打开详情页（默认不自动播放）

### Non-Goals
- 不新增独立服务端页面路由（默认使用 `/?podcast=<id>`）
- 不引入新后端存储或外部依赖
- 不做账号体系或权限控制

## Decisions

### 1. 分享链接方案
**决定**：采用 `/?podcast=<id>` 查询参数作为分享链接。

**原因**：
- 无需新增服务端路由
- 兼容现有静态页面入口
- 便于复制与解析

### 2. 详情页形态
**决定**：使用底部抽屉 + 遮罩作为详情页容器，支持点击与上滑进入。

**原因**：
- 与底部播放器布局一致
- 移动端操作自然
- 便于在不打断播放的前提下展示信息

### 3. 数据来源
**决定**：复用 `GET /api/podcasts` 与 `GET /api/podcasts/:id` 返回的元数据字段（含 `sourceUrl`）。

**原因**：
- 现有 `podcastStore` 已持久化 `sourceUrl`
- 无需新增后端逻辑

### 4. 自动播放策略
**决定**：通过分享链接进入时仅打开详情页，不自动播放。

**原因**：
- 避免移动端自动播放限制
- 防止误触导致声音播放

### 5. 复制策略
**决定**：优先使用 `navigator.clipboard`，失败时降级到 `execCommand('copy')` 并提示结果。

## Risks / Trade-offs
- 分享链接不是独立页面路径，SEO 不友好但实现成本最低
- 详情页抽屉与播放器区域交互需要精细化点击过滤

## Migration Plan
- 无数据迁移需求，仅前端改动

## Open Questions
- 是否需要 `/p/<id>` 形式的独立路由
- 是否需要在详情页支持编辑/更新原文链接
